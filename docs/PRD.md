## 1. 项目概述

### 1.1 定位

Codex-Pulse 是面向 macOS 与 Windows 用户的 Codex 桌面辅助工具。通过菜单栏/托盘应用、悬浮胶囊、桌面小组件和数据看板，实时展示 Codex 的账号状态、使用额度、Token 消耗、任务运行状态及额度重置时间。

用户无需频繁打开 Codex 设置或在终端执行 `/status`，即可在桌面掌握运行与用量全貌。

**主打：** 本地运行、实时监控、低干扰展示。  
**定位：** Codex 用户的桌面状态中心和使用分析助手。

### 1.2 一句话介绍

Codex-Pulse 是一款运行在 macOS 菜单栏/桌面和 Windows 托盘上的 Codex 使用监控工具，帮助用户实时查看账号、额度、Token、任务状态和重置时间，让每一次 Codex 使用都清晰可控。

### 1.3 宣传语

- 让 Codex 的每一个 Token，都清晰可见。
- 不用打开 Codex，也能掌握 Codex。
- 额度、Token、任务状态，一个小组件全部掌握。

### 1.4 用户可快速掌握的信息

- Codex 当前是否正在运行
- 当前使用的账号和订阅套餐
- 当前额度已经使用多少
- 各额度窗口什么时候重置
- 今日、近七天和累计使用了多少 Token
- 当前任务运行了多长时间
- 哪个项目正在执行 Codex 任务
- 是否有任务完成、失败或等待用户授权

## 2. 目标用户

1. 经常使用 Codex CLI、Codex App 或 IDE 插件的开发者  
2. 同时运行多个 Codex 项目和任务的重度用户  
3. 需要关注五小时、每日、每周等额度窗口的 Plus、Pro 或团队用户  
4. 希望分析 Token 消耗和模型使用效率的开发者  
5. 经常让 Codex 执行长时间任务、需要及时了解运行状态的用户

## 3. 核心价值

### 3.1 无需打开 Codex 即可查看额度

在 macOS 菜单栏或桌面小组件中直接显示额度使用进度、剩余额度比例和重置倒计时。

### 3.2 实时了解任务状态

清楚展示 Codex 当前是运行中、等待授权、已完成、已停止还是发生错误，避免用户频繁切换到 Codex 查看进度。

### 3.3 统计真实 Token 使用情况

展示累计 Token、每日 Token、使用趋势、峰值使用量和连续使用天数，帮助用户了解自己的 Codex 使用习惯。

### 3.4 提前进行额度预警

当额度使用达到设定阈值时发送系统通知，避免在重要任务执行过程中突然触发限额。

### 3.5 本地优先保护隐私

数据主要通过本机 Codex App Server 获取和处理，不上传用户代码、任务内容、账号凭证或项目文件。

## 4. 核心功能

### 4.1 桌面额度小组件

提供小、中、大三种 macOS 小组件。

#### 小尺寸

- 当前额度使用百分比  
- 剩余额度百分比  
- 距离重置剩余时间  
- Codex 当前运行状态  

#### 中尺寸

- 主额度窗口  
- 次级额度窗口  
- 今日 Token 使用量  
- 当前任务状态  
- 当前使用模型  

#### 大尺寸

- 多个额度窗口  
- 近七天 Token 趋势  
- 当前运行任务  
- 最近完成任务  
- 重置卡数量  
- 额度预警状态  

**说明：** 额度数据应动态读取，不在客户端写死「五小时」或「每周」等规则。官方接口可返回额度使用百分比、窗口时长和下一次重置时间，但不保证每个账号都会返回明确的绝对总额度。

### 4.2 macOS 菜单栏应用

用户点击菜单栏图标后，快速查看完整状态。

#### 菜单栏图标状态色

| 颜色 | 含义 |
|------|------|
| 绿色 | Codex 空闲且额度充足 |
| 蓝色 | Codex 正在运行 |
| 黄色 | 任务等待确认或额度较低 |
| 红色 | 额度耗尽、任务失败或登录失效 |
| 灰色 | Codex 未启动或未登录 |

#### 菜单栏面板内容

- 当前账号邮箱  
- Plus、Pro、Business 等套餐类型  
- 当前认证方式  
- 主额度使用进度  
- 次级额度使用进度  
- 额度重置倒计时  
- 今日 Token  
- 当前任务  
- 快捷操作按钮  

### 4.3 账号信息

显示当前 Codex 账号信息：

- 登录状态  
- 账号邮箱  
- 套餐类型  
- ChatGPT 登录或 API Key 登录  
- Codex CLI 版本  
- 当前工作空间  
- 最近同步时间  

**数据来源：** Codex App Server 的 `account/read` 可返回当前认证模式、邮箱及套餐类型。

**安全要求：** 工具不应直接读取、复制或上传用户的 Codex 登录凭证，而应通过官方 App Server 的账号接口完成登录状态读取。

### 4.4 额度监控

显示所有可用的 Codex 限额窗口：

- 限额名称  
- 已使用百分比  
- 剩余百分比  
- 窗口持续时间  
- 下一次重置时间  
- 重置倒计时  
- 是否已经触发限额  
- 剩余 Credits  
- 可用额度重置卡数量  
- 重置卡过期时间  

**数据来源：** 通过 `account/rateLimits/read` 获取额度信息，并监听 `account/rateLimits/updated` 实时更新。官方接口支持多额度桶、使用百分比、窗口时长、重置时间及可用重置卡信息。

### 4.5 Token 使用统计

Token 数据面板显示：

- 今日 Token 使用量  
- 昨日 Token 使用量  
- 近七天 Token 使用量  
- 近三十天 Token 使用量  
- 累计 Token 使用量  
- 单日 Token 峰值  
- 每日 Token 趋势图  
- 当前连续使用天数  
- 历史最长连续使用天数  
- 单次运行时间最长的任务  

**数据来源：** 官方 `account/usage/read` 可返回累计 Token、每日 Token 桶、单日峰值、最长任务时间和连续使用天数；部分账号或指标可能返回空值，界面需兼容处理。“今日 Token”取官方值与本机当天全部 session JSONL `token_count`/第三方响应 `usage` 汇总中的较大值，账号、认证方式或自定义 provider 切换后立即重读，不需要重启。DeepSeek 等第三方只返回 0 时允许基于已落盘会话文本进行本地估算，但必须在展开详情中标明估算来源并声明不是服务商账单。由于本机日志不携带账号 ID，今日标题是设备汇总口径；生命周期累计与原生 ChatGPT 历史桶仍按远端账号隔离。

### 4.5.1 可选信息任务栏

信息任务栏默认关闭。用户确认地区后，可在胶囊左侧显示与玻璃背景融合的 Meteocons 动态天气 SVG，并在胶囊下方显示温度、地区、星期和该地区本地时间。素材随应用离线分发，太阳、云、雨、雪、雾和闪电动画由素材自身提供，不请求图片 CDN。开启时天气视觉取代原状态灯，但思考中与等待授权的任务灯带继续保留；展开详情卡片时临时隐藏下方信息栏，收起后恢复。macOS 与 Windows 均保存城市、经纬度和 IANA 时区；网络失败保留最近一次成功天气，不使用演示值冒充实时天气。

### 4.6 模型质量、成本与速度排行榜

完整看板接入 Artificial Analysis Data API，仅展示 OpenAI 模型并提供：

- 模型质量榜：按 Artificial Analysis Intelligence Index 降序  
- 任务成本榜：按每个 Intelligence 任务的官方估算成本升序  
- 输出速度榜：按中位输出 Token/秒降序，并辅助展示首 Token 延迟  
- 官方数据来源与更新时间  
- 12 小时本地公开数据缓存与手动刷新  

用户在设置中填写自己的 API Key。密钥仅保存于 macOS Keychain，不进入源码、普通设置、日志、Widget 或导出文件；模型字段缺失时只隐藏对应指标，不影响整页数据。

## 5. 特色扩展功能

### 5.1 额度消耗预测

根据最近一小时、一天和七天的使用速度，计算：

- 当前额度预计还能使用多久  
- 按照当前速度是否会提前耗尽  
- 距离重置前预计剩余额度  
- 建议切换到更轻量模型的时间  

**示例：**  
> 按照最近两小时的使用速度，当前额度预计还能使用 1 小时 35 分钟，距离重置还有 3 小时 20 分钟。

### 5.2 额外额度重置预测

该功能只预测额外重置、补偿重置、Banked Reset、临时扩容、套餐限额调整和官方活动，不包含正常 5 小时或每周额度恢复。

- 免费监控 OpenAI Status、官方帮助中心、OpenAI News、Codex 更新日志和 OpenAI Codex GitHub 发布源
- 可通过用户选择的 Nitter、RSSHub 或自定义 RSS 代理监控 `@OpenAI`、`@OpenAIDevs`、`@sama`、`@thsottiaux`
- Codex-Pulse 不保存 X 登录账号或 Cookie；第三方代理的实现方式、稳定性与可信度由代理提供者决定
- 第一版采用透明规则评分、半衰期衰减、多源加成与事件去重
- Status 单一来源指数最高为 55，除非同时出现官方账号或关键人员相关信号
- 输出“重置预测指数 0～100”、等级、预计窗口、可信度、实际依据和历史记录
- 未经历史事件校准前不得称为概率或显示概率百分比
- 第三方 RSS 信号必须明确标记，不能在没有官方免费来源印证时单独触发“官方确认”
- 无证据时显示“暂无额外额度重置信号 / 当前仅显示正常额度恢复时间”

明确官方确认时指数为 100；已完成并超过 24 小时的重置移入历史，不继续作为即将发生的信号。

### 5.3 Codex 使用效率分析

根据任务结果和 Token 消耗生成效率指标：

- 每个完成任务平均 Token  
- 每个项目平均 Token  
- 不同模型 Token 消耗对比  
- 成功任务与失败任务比例  
- 任务平均运行时长  
- 返工次数  
- 用户中途干预次数  
- 每千 Token 修改的有效代码行数  

### 5.4 每日与每周报告

自动生成使用报告，包含：

- 本周共运行多少个任务  
- 总计使用多少 Token  
- 哪个项目消耗最多  
- 哪个模型使用最多  
- 最长任务运行时间  
- 失败任务数量  
- 高峰使用时段  
- 额度触发次数  
- 与上周相比的变化  

报告可导出为 Markdown、CSV 或图片。

### 5.5 多客户端状态汇总（后续）

可汇总：

- Codex App  
- Codex CLI  
- VS Code Codex 插件  
- Cursor 中的 Codex  
- 远程 SSH 主机中的 Codex  
- Codex Cloud 任务  

让用户在一台 Mac 上查看本地和远程 Codex 的统一状态。

## 7. 技术方案

### 7.1 macOS 客户端技术栈

建议采用：

- Swift  
- SwiftUI  
- WidgetKit  
- MenuBarExtra  
- App Intents  
- UserNotifications  
- Charts  
- Keychain  
- SQLite 或 SwiftData  
- App Groups  

使用原生 SwiftUI，便于支持菜单栏、桌面小组件、系统通知、开机启动和低功耗后台运行。

### 7.2 Codex 数据接入

客户端在本机启动：

```bash
codex app-server
```

通过标准输入输出与 Codex App Server 建立 JSONL 通信，并按 JSON-RPC 协议发送请求、接收响应和监听事件。

官方 App Server 默认支持基于标准输入输出的 JSONL 通信，也支持 Unix Socket；WebSocket 当前仍属实验性方式，第一版建议优先使用标准输入输出或 Unix Socket。

#### 主要调用接口

```text
account/read
account/rateLimits/read
account/usage/read
account/workspaceMessages/read
thread/list
thread/read
thread/loaded/list
```

#### 主要监听事件

```text
account/updated
account/rateLimits/updated
turn/started
turn/completed
item/started
item/completed
item/agentMessage/delta
```

Codex Hooks 可辅助获取当前会话 ID、项目目录、模型和会话记录路径。

### 7.3 本地数据存储

本地数据库保存：

- 每日额度快照  
- Token 使用记录  
- 项目统计  
- 历史任务  
- 通知记录  
- 用户设置  

账号凭证存储在 macOS Keychain 中；普通统计数据存放在 App Group 共享目录，供主应用和桌面小组件共同读取。

## 8. 隐私与安全

项目遵循本地优先原则：

1. 不上传用户源码  
2. 不上传任务对话  
3. 不读取项目文件内容进行分析  
4. 不明文保存登录凭证  
5. 不直接解析或复制 Codex 的认证文件  
6. 不向第三方服务器上传账号邮箱和用量数据  
7. Webhook 功能默认关闭  
8. 所有外部通知必须由用户主动启用  
9. 提供一键清除本地数据功能  
10. 对使用重置卡、停止任务等操作进行二次确认  
11. Artificial Analysis 请求只携带用户提供的 Key 与分页参数，不上传 Codex 账号、额度、任务、项目或对话数据  
12. Codex 邮箱在菜单栏、看板、连接状态、日志及诊断信息中统一脱敏显示  
13. 额外重置预测不要求用户提供 X、OpenAI 或 GitHub 登录凭证；可选第三方 RSS 代理只保存 URL 模板，不保存代理服务端使用的账号或 Cookie

## 11. 产品差异化

Codex-Pulse 不与官方 Codex App 竞争代码编辑和任务执行能力，而是专注于：

- 用量可视化  
- 额度监控  
- Token 分析  
- 运行状态提醒  
- 多项目统计  
- macOS 桌面小组件  
- 本地隐私保护  

它更像是 Codex 的「活动监视器」和「仪表盘」，解决重度 Codex 用户无法持续、直观地掌握额度和任务运行状态的问题。
